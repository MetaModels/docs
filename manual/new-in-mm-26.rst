Changes and Features in MM 2.6
===============================

The following is an overview of the changes and features in MetaModels 2.6, made possible by the
"**early adopter program**" (EAP) — more information under **Fundraising** on the
`MM website <https://now.metamodel.me/de/unterstuetzer/fundraising#metamodels_2-6>`_.

For a **check after upgrading** to MM 2.6, see :ref:`further notes below <check_upgrade_mm260>`.


General and Core
----------------

MetaModels 2.6 requires **Contao 6.x** and **PHP 8.4** — as well as, currently, an
`EAP access key <https://now.metamodel.me/de/unterstuetzer/fundraising#metamodels_2-6>`_.

.. note:: **The target version for MM 2.6 is Contao 6.3 (LTS)** - until that version we work on the dev version, i.e.
   all adjustments are provisional because things in Contao may still change.

The most important new features are:

* **API and MCP for AI agents**: The records of the MetaModels are accessible via the Contao API (read, create,
  change, delete — with the permissions and validation of the backend), see :ref:`Contao API <rst_extended_contao-api>`.
  Via Contao's MCP server, an AI agent can also read and set up MetaModels, see
  :ref:`MCP administration <rst_extended_mcp-admin>` or :ref:`rst_cookbook_mcp_event-management`
* **Blocks in the wrapper templates**: The templates ``mm_filter_default``, ``mm_clearall_default`` and
  ``mm_pagination`` are divided into Twig blocks (since MetaModels 2.5.2, also included in 2.6). A custom template
  extends the default template and overrides only the desired block, see :ref:`component_templates_twig-blocks`.


Known Issues
------------

* when switching to/from debug mode in the BE via button, the reference page is no longer correct and you have to
  navigate to the page again — e.g. with "back" in the browser and a page reload |br|
  The cause is the switch link ``?do=debug&key=enable&referer=…`` generated by Contao: on the route-based
  MetaModels backend pages (e.g. ``/contao/metamodel/mm_employees``), the ``referer`` parameter remains **empty**,
  so that after switching, Contao returns to the backend dashboard instead of the original page. This affects
  Contao's own debug switch and is not covered by the new referer handling of DC_General (own "Back" buttons) —
  Contao offers no way to influence the referer at this point. |br|
  A fix has been proposed: `contao/contao PR #10206 <https://github.com/contao/contao/pull/10206>`_.

Checklist for Upgrading to MM 2.6
----------------------------------

In general, an upgrade within the MM 2.x branch is straightforward; any necessary label adjustments
and DB changes are handled via migrations. However, there are a few things that cannot or can only very
difficultly be caught by migrations. For this reason, the following points should be kept in mind when
upgrading to MM 2.6:

* **Custom templates in the** ``.html5`` **format**: In MetaModels 2.6 the ``.html5`` templates are gone, the supplied
  templates are Twig templates (``.html.twig``). Flat overrides in the project ``templates/`` folder (e.g.
  ``templates/mm_filter_default.html5``) are no longer taken into account and must be recreated as ``.html.twig``,
  preferably under ``templates/metamodels/<group>/…``. For the wrapper templates of the filter, the filter reset and the
  pagination, an ``{% extends %}`` with the affected block is sufficient, see :ref:`component_templates_twig-blocks`.
  The changeover is described under :ref:`new_in_mm250`.
